# DoneBot 数据备份与回滚

在线管理后台的“回滚版本”只替换程序，不回退数据库，也不删除文件或 Redis 任务。迁移由程序启动时自动向前执行。已经发放安装凭据、存储资产或保存存储策略的实例，不应执行清表、删列的数据库降级；应优先部署兼容当前数据库的修复版本。确需恢复旧数据库时，必须使用经过验证的完整备份。

## 升级前备份

1. 暂停入口流量和新任务提交，等待正在生成、计费的任务完成；核对是否还有供应商已接受但尚未结算的任务。停止所有网关副本及后台 worker，防止备份期间继续写入、清理对象或扣费。
2. 备份整个 PostgreSQL 数据库，包含 `schema_migrations`、用户余额、用量记录、`api_keys`、`donebot_installs`、`assets`、`asset_owners` 和 `settings`。只导出 DoneBot 新表不能恢复一致的凭据、归属与账单。
3. 在同一维护窗口保存 Redis 的持久化快照/AOF，覆盖异步任务、任务归属、待计费记录、结算队列及计费去重状态。仅恢复数据库、丢弃 Redis 会造成任务不可查或重复结算。
4. 备份本地资产目录及 S3/R2/OSS 对象版本，同时保留上传和生成两个用途使用过的所有目录、桶和前缀。不能只备份当前管理页里的默认后端：历史资产按每行 `storage_config` 保存的原配置访问。
5. 安全保存部署配置、环境变量、JWT 签名密钥和存储配置加密密钥，以及备份中历史后端需要的访问凭据。备份包含 API Key 和存储秘密，应加密、限制权限，不能上传到代码仓库或粘贴进工单。

例如，在已配置 `PGSERVICE=donebot` 的维护主机上执行，避免把数据库密码放进命令行：

```sh
umask 077
backup_dir="/secure/backups/donebot-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
pg_dump --dbname=service=donebot --format=custom --file="$backup_dir/database.dump"
pg_restore --list "$backup_dir/database.dump" > "$backup_dir/database.contents"
```

`pg_restore --list` 只能验证归档可读，不能代替恢复演练。将数据库、Redis、对象及密钥在隔离环境恢复，使用备份对应版本验证：安装凭据仍可鉴权且不能从普通 Key 管理读取；资产归属、下载及解密正常；余额、用量及已结算任务一致。记录备份时间、程序提交/版本和供应商未完成任务清单。

## 有业务数据时恢复

先关闭所有网关实例和 worker，并额外保存故障现场的数据库、Redis 和资产副本。将已验证的旧快照恢复到独立的新环境，使用与该快照兼容的程序、配置和密钥；验证后再切换流量。不要把新旧数据库、Redis 的计费状态混用。

快照恢复会回到备份时点，备份后新增的用户、充值、安装、任务和扣费不会自动合并。运营方必须核对这些增量，以及上游已经完成/已收费的任务，确认恢复点和补账方案后再开放写入。数据库回滚不能撤销供应商已经产生的费用。

安装凭据只有发放响应可让客户端保存明文；服务端鉴权依赖 `api_keys.key` 的原值。禁止覆写该字段“擦除”凭据，也禁止删除 `donebot_installs` 来释放映射：否则现有凭据会失效，或被当成可读取的普通 Key。旧版本如果不具备安装凭据隐藏逻辑，不应直接接到含安装 Key 的现有数据库上。恢复完整备份可保留备份时点的凭据及映射，已被旧脚本覆写且没有原值备份的凭据无法从其 MD5 片段恢复。

## 空环境的数据库降级

`backend/migrations/down/` 是手工执行的脚本，不会由启动迁移或管理后台在线回滚自动执行。仅在没有相应数据的测试/空环境使用；三个脚本都包含事务、与启动迁移共用的互斥锁，以及检查期间阻止并发写入的表锁。

| 脚本 | 拒绝执行的情况 |
|---|---|
| `252_donebot_storage_policies.sql` | 任意资产或所有权记录；`settings.key='donebot_storage_policies'` 存在。单个 upload 资产也受保护，不能假设其历史存储配置可以丢弃。 |
| `251_assets.sql` | 252 尚未回退；任意资产或所有权记录。 |
| `250_donebot_installs.sql` | 251/252 尚未回退；任意安装记录，包括已吊销安装；任何残留的 `sk-donebot-` 凭据，包括没有安装映射的异常记录。 |

普通的 `donebot.group_id`、自动创建的分组及其他无模式依赖的设置不构成空环境降级的阻碍，也不会被脚本删除。已有业务数据时，脚本会报错并保留原始凭据、映射、资产、策略和迁移标记；不要删除记录、合并跨用途资产或删迁移标记来绕过保护。

完成备份并停止所有副本后，在仓库根目录按 **252 → 251 → 250** 顺序执行。`ON_ERROR_STOP` 保证当前脚本出错时立即退出；只有上一条命令成功才继续下一条：

```sh
psql --dbname=service=donebot --set=ON_ERROR_STOP=1 --file=backend/migrations/down/252_donebot_storage_policies.sql
psql --dbname=service=donebot --set=ON_ERROR_STOP=1 --file=backend/migrations/down/251_assets.sql
psql --dbname=service=donebot --set=ON_ERROR_STOP=1 --file=backend/migrations/down/250_donebot_installs.sql
```

每个文件各自原子提交，三份文件合起来不是一笔事务：例如 252 成功、251 被数据保护拒绝时，数据库停在已回退 252 的状态。停止后续操作并核对状态；若需要恢复当前版本，启动当前程序即可重新应用缺失的向前迁移。交互式 `psql` 会话遇到异常后需先执行 `ROLLBACK;` 释放事务与锁，再处理其他命令。不要在外层再套 `--single-transaction`。

重新升级时，启动迁移按 **250 → 251 → 252** 执行，重新创建表、列、索引并记录原始校验和。不得修改已发布的向前迁移 SQL，或人为写入 `schema_migrations` 伪装完成。数据库降级后若马上启动当前程序，向前迁移也会立即重建这些结构。

## 验证命令

以下集成测试只创建并销毁专用 PostgreSQL 容器，不连接部署数据库：

```sh
go -C backend test -tags integration ./migrations -run '^TestDoneBot' -count=1
```

覆盖活动/吊销安装及原凭据保护、孤立凭据、上传/生成/跨用途重复资产、历史存储配置和所有权保护、策略设置保护、执行顺序、中途 SQL 失败的事务回滚，以及空库完整 down/up 后继续创建两种用途的资产。
