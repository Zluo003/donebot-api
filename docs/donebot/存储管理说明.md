# DoneBot 存储管理

管理员进入 DoneBot → 存储，分别配置“上传存储”和“生成产物存储”。上传素材使用独立策略；视频、音乐和异步图片共用同一套生成产物策略，不按媒体类型拆分容量。

## 快速设置

1. 在 DoneBot → 存储设置上传与生成产物两组策略，填写本地目录或 S3 凭据，以及公网地址。
2. 配置容量、保存小时数和清理阈值，点击“保存存储设置”；“刷新用量”更新占用。
3. 需要转存视频时，在视频账号选择“系统存储策略”；默认“转发 URL”保留上游链接。

## 配置与清理

两个策略都支持本地目录或 S3 兼容存储（R2、OSS、MinIO），各自设置最大总容量、单文件上限、最长存储时长和容量清理阈值。页面显示当前占用及文件数，刷新用量不会覆盖未保存的修改。保存后运行时生效。

两套策略的驱动、目录、Bucket、对象前缀与公开地址均可不同，例如上传使用本地目录，生成产物使用 S3。无需让 `image_storage.driver` 与 `asset_storage.driver` 相同。

| 配置 | 范围或语义 |
| --- | --- |
| 最大总容量 | 页面以 GiB 输入，接口使用字节；必须大于 0 |
| 单文件上限 | 页面以 MiB 输入，接口使用字节；必须大于 0 |
| 最长存储时长 | 1–8760 小时 |
| 清理阈值 | 1–100%；例如 90%，超过后从最早文件开始删除，直到占用不高于阈值 |
| 本地目录 | 必填；需确保进程可写及磁盘持久化 |
| 公网访问地址 | HTTP(S) URL；上传存储可留空使用请求的网关地址，启用的本地生成产物必须填写 |
| S3 Endpoint / Region | Endpoint 可留空使用 AWS S3；Region 可留空使用 `auto` |
| S3 Bucket / Access Key / Secret | 启用 S3 时必填；已有 Secret 留空表示保留，不回显原值 |

初始策略为上传总容量 10 GiB、单文件 32 MiB，生成产物总容量 50 GiB、单文件 256 MiB；两者默认保存 168 小时、阈值 90%。S3 支持对象前缀和 Path Style。S3 保存时长超过 168 小时必须配置公网访问地址，预签名链接最长只支持七天；保存 S3 密钥需要部署固定的 `TOTP_ENCRYPTION_KEY`，沿用现有加密链路。管理读取接口只返回 `secret_configured` 状态，提交新密钥后界面会清空密钥输入。

后台尚未保存策略时，上传策略从 `asset_storage` 初始化；生成策略先继承上传的连接信息并使用独立目录/前缀，在旧 `image_storage` 已启用且 S3 配置完整时继承其 S3 配置。配置文件中的 `asset_storage.s3.prefix` 默认是 `assets/`，生成策略缺省前缀为 `generated/`；旧 `image_storage.prefix` 可覆盖生成初始前缀。后台保存后以 `donebot_storage_policies` 中的两套策略为准，修改配置文件不会覆盖已保存策略。

兼容旧 S3 配置时，上传公开地址优先使用 `asset_storage.public_base_url`；仅当上传驱动为 `s3` 且该值为空时，回退到 `asset_storage.s3.public_base_url`。本地上传不会借用 S3 地址。生成策略从完整的旧 `image_storage` S3 配置初始化时，继续使用它自己的公开地址和 Bucket，不会被上传地址覆盖。

`asset_storage.driver` 是上传初始驱动的唯一选择。嵌套的 `asset_storage.s3.enabled` / `asset_storage.s3.driver` 来自复用的旧配置类型，为兼容保留，设置它们不会启用、停用或切换存储。后台每套策略通过自身 `enabled` 和 `driver` 控制。

视频账号的“上游产物存储方式”默认为“转发 URL”；选择“系统存储策略”才将 Seedance 视频转存至共享生成产物存储。直接转发的供应商 URL 不受网关本地容量或保留时间控制，期限由供应商决定。

## 管理接口

`GET /api/v1/admin/donebot/storage` 读取两个策略与用量；`PUT` 同路径保存 `{upload, generated}`。每个策略的字段：

```text
enabled, driver(local|s3), local_path, public_base_url,
max_storage_bytes, max_file_bytes, ttl_hours, cleanup_threshold_percent,
s3: {endpoint, region, bucket, prefix, access_key_id, secret_access_key, force_path_style}
```

读取另返回 `usage_bytes`、`file_count`、`secret_configured`；`secret_access_key` 返回空字符串，保存时留空保留原密钥。修改复用已有管理员权限及 step-up 链路。

本地对象目录及数据库应使用持久化卷。切换目录、驱动或 Bucket 后，旧文件继续按每条记录的原存储配置读取和删除，重启后仍可访问；配置切换不会迁移旧文件。缩短 TTL 会立即缩短旧记录的有效期，增加 TTL 不延长旧文件寿命。过期读取立即拒绝，后台每分钟清理过期对象。单个文件超过容量阈值时直接拒绝，不清理其他文件；普通写入超阈值时按最早文件顺序清理至阈值内。真实 S3 权限、域名可达性和供应商产物转存仍需使用部署环境联调，本轮界面和回归测试使用本地 fixture，未调用真实付费供应商。

## Redis 与请求重试

异步图片任务元数据及其幂等映射、未完成的 APIMart/Seedance 结算队列依赖 Redis，不能从已落盘的媒体文件或 PostgreSQL 使用记录完整重建。生产必须启用 Redis AOF、持久化 Redis 数据目录并验证恢复流程。Compose 模板使用 `appendfsync everysec`，故障时仍可能丢失最近约一秒的写入；需要逐次落盘时使用 `appendfsync always` 并评估吞吐。AOF 不替代备份与生产恢复演练，也不要对这些键执行 `FLUSHDB` 或 `FLUSHALL`。

Redis 故障的影响依请求路径而定：余额缓存读取失败会回源数据库，余额源也不可用时返回 503；通用在途预留的 Redis 操作失败可沿原策略放行，但余额计费的正价 APIMart/Seedance 异步创建要求有效预留，缺少预留或无法写入结算队列会返回 503。异步图片任务创建、查询和状态持久化失败也不会按成功处理；已成功入队的 APIMart/Seedance 结算任务在 Redis 恢复后由后台继续尝试结算；旧异步图片正在执行的上游请求不会在进程重启后自动重放。供应商已经收到请求后，网关持久化失败仍可能返回 503，不表示供应商一定未创建任务。

`idempotency.observe_only` 只控制已接入通用协调器的管理及部分用户写接口；它不是模型调用的全局幂等开关。异步图片有独立的可选 `Idempotency-Key` 机制：同一用户/安装凭据、同一 Key 和相同请求重放返回同一任务，不同请求返回 409；不带 Key 每次创建新任务。图片 Key 至少保留 24 小时，超过窗口不要复用旧 Key。关闭 `observe_only` 不会使图片接口强制要求 Key，也不让其他未接入幂等的原生请求自动获得重放保护。
